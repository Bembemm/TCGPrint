# Fase 12 — Duplex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` inline. Steps use checkbox syntax for tracking.

**Goal:** Add reproducible per-card backs, DFC resolution, and physically paired duplex export while preserving existing front fidelity and shared pagination.

**Architecture:** Extend `WorkingCard` and Project v4 with explicit back state and immutable Back Library references. A pure `core/duplex` layer transforms the placements returned by `calculateGridPagePlacements`; PDF, preview, and validation consume that same plan. Project-based export reads the saved revision as authority.

**Tech Stack:** TypeScript, Next.js 16.3 route handlers, existing SQLite repositories/content-addressed artwork originals, shared geometry, lossless PDF engine, Vitest.

**Spec:** `IMPLEMENTATION_PLAN.md` Phase XII-A and XIV; user handoff for Phase 12; ADRs 0002, 0005, 0006, 0010, 0013, 0014.

## Global Constraints

- Work only on `feature/fase-12-duplex`, based on `bba5a7fe52758b273ee9e5de5fe1fda5c0c08399`; never modify `main` or merge.
- Reuse `WorkingCard.faces`, `selectedArtworkByFace`, MPC face references and `sharedMpcCardback`; never conflate DFC backs, Project generic backs, or MPC shared cardbacks.
- Preserve schema v1/v2/v3 reads; write schema v4; old Projects remain front-only by default.
- Keep `calculateGridPagePlacements` as the only paginator. Blank, skipped, and reserved slots stay physical and never compact.
- Use millimeters and page-space placement transforms; keep artwork upright and unmirrored, JPEG streams untouched, and front-only geometry unchanged.
- A manual back remains locked across re-resolution and Project-default changes; only an explicit restore-auto/default action clears it.
- Back Library references are immutable `assetId + SHA-256`; a retired library record remains resolvable while its content-addressed original exists.
- Duplex has nominal geometry only. Do not add calibration, offsets, scaling correction, skew, or hidden printer adjustments.
- `front-back-separated` creates distinct front and back PDFs plus a deterministic manifest; the ZIP is packaging only. Front-only and back-only remain independently exportable.

## Review Focus

- Does a back stay upright while its physical slot moves? Test asymmetric `TOP ↑` artwork independently from slot mapping for all four orientation/flip combinations.
- Can an old Project or recovery resolve a retired Back Library record? Test immutable ID/hash resolution through reopen and recovery.
- Can a request mix two Project revisions or submit unsaved back selections? Test exact persisted snapshot selection and stale revision rejection.
- Do partial pages, skipped slots, blank backs, and quantity preserve each physical pairing? Test page 1/page 2 and numbered slot fixtures.
- Does duplex leave PDF image bytes and cut-template geometry unchanged? Test JPEG stream identity, front placement, and exact cut source/hash/trim.
